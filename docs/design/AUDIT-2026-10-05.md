# Code audit, 2026-10-05

Scope: everything built since P33b (cards crossover, relics, events, run codes, Echoes, Clubs, seasons, cosmetics, watch/announcements) plus the exit and cell-release code those touched. Method: read the new code for exploits, crash windows, input trust and lifecycle leaks; grep the whole tree for the usual smells (unguarded admin commands, swallowed exceptions, unbounded client input, static mutable state); fix what was real and test it.

## Fixed in this audit

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | **High (economy)** | **Club weekly reward could be claimed repeatedly.** `leave` and `kick` erased the member's claim record, so claim, leave, rejoin (an alt owner re-invites), claim again paid CobbleDollars without limit. Joining a second club that had met its goal paid again too. | The claim record now outlives leaving and kicking, and `claim` refuses anyone who has claimed this week in any club. Unit test `claimCannotBeRepeated`. |
| 2 | **Medium (economy / integrity)** | **Run codes made loot replayable.** Loot was rolled from the run seed, a run code carries the seed, and a code can be hand-written (its check is one character). A player could search offline for a seed with a jackpot table and replay it. Seeds were random before P35. | Loot now rolls from the seed mixed with the run's own id (`RewardBankService.lootSeed`). Opponents, bosses and draft cards still match a shared code, as designed; loot does not. |
| 3 | Medium (lost reward) | **Season track grants could be lost in a crash.** The step count was saved before the rewards were queued; a crash between the two lost a prize (such as the season trim template). | Rewards are queued first (flushed, and deduplicated by grant so a replay adds nothing), then the step count is saved, then the player is told and the delivery runs. `TowerPendingRewardStore.addIfAbsent`. |
| 4 | Medium (bug) | **A watcher who started a run of their own would be sent home mid-run** when the run they had been watching ended. | `Watching.sweep` drops a watch the moment the watcher has a run, restoring their game mode and camera without a teleport. |
| 5 | Low | Watching from inside a Cobblemon battle would switch the player to spectator and move them mid-battle. | Refused: "Finish your battle first." |
| 6 | Low (bug) | **Run codes broke for any tower or mode id containing a hyphen** (a legal id character that is the code's own separator): the code encoded but never decoded. | A hyphen is written as `~` (never legal in an id). Round-trip test. |
| 7 | Low (display) | `/tower season track` and the step message showed `{color}` / `{season_name}` unexpanded for banner steps. | `describeStep` expands every token and uses the grant's label. |

## Checked and found sound

- **Admin commands**: every `*admin` command requires permission level 2.
- **Client packets**: every client-to-server payload is validated server-side (unknown tower or tab falls back, malformed ids are caught and refused, a rental pick is range-checked, a purchase is checked against the player's own run). Strings use the vanilla 32k cap.
- **Season points**: caps, once-per-period keys and the daily total behave as documented; replay is a no-op.
- **Finalisation**: three idempotent steps with stored progress, no loot granted, crash-tested.
- **Club names and tags** are `[A-Za-z0-9_]` only and are shown as plain literals, so a tag cannot inject formatting codes.
- **Exhibition (Echo) battles** run on a cloned, healed party; nothing touches the real one.
- **Placeholder API** is reached only through a guarded bridge (`LinkageError` caught), so the mod runs without it.
- No `TODO`/`FIXME`, no `printStackTrace`, no empty `catch`; the broad `catch (Exception)` sites are all definition loaders that log and skip.

## Open: judgment calls and known limits (not changed)

1. **Chosen seeds can be used to cheese the Speed and Difficulty boards** (pick a seed with weak opponents). Loot is now safe, but the boards are not. Options: runs started from a code do not count for boards, or they are marked on the board. Needs an owner decision.
2. **Cell allocation is synchronous on the server thread** (about 325,000 blocks a cell). A burst of hundreds of runs a minute can stall the server past the 60 s watchdog. Ordinary play is fine. A real fix is asynchronous or queued preparation.
3. **A corrupt saved-data file is silently reset by vanilla** (it logs and starts empty) and then overwritten at the next save. Our loaders use `getUUID` and friends without guarding. No backups are kept. Consider a copy-on-load of the `cobbletowers_*.dat` files.
4. **A watcher is exempt from the exit sweep for as long as the run lives** and can fly into other cells. Spectator mode makes this harmless, but it also lets a watcher scout a team's upcoming floors and relay them. Anyone can watch anyone; a per-player opt-out is a likely follow-up.
5. **Club tags have no profanity or impersonation filter** (a club can call itself `STAFF`).
6. **The mod's version label still reads `0.21.0-p21-reward-revamp`**, though it contains P36e. Renaming changes the jar name that the smoke scripts and docs use, so it was left alone.
7. **Finished runs are only pruned at startup**, so a very long uptime holds every run since the last restart in memory and walks them once a second in the exit sweep.
8. The tab-list overlay, the watcher's camera panel and the booster-pack delivery were never seen in a real client or with the card mod.
